# 知识问答控制台 · 操作手册

本文档介绍 **knowledge_router** 控制台的全部功能与推荐工作流。

## 1. 概述与架构

本系统是一套「知识库 + 标准问题 JSON」问答匹配服务：

- **LLM 仅做语义匹配**：根据用户问题，从知识库全部标准问题中选出最匹配的条目 ID（输出 `q001` 或 `NONE`）
- **回答直接查表**：匹配成功后，从内存中的 FAQ JSON 返回预存回答，无需 LLM 生成正文
- **Top K 候选**：可同时返回多个候选匹配及置信度，便于调试

控制台地址：`http://localhost:8001`（默认端口，以实际启动脚本为准）

---

## 2. 启动与连接

### 2.1 首次启动

```powershell
cd knowledge_router
copy .env.example .env
# 编辑 .env 填写 API_KEY 等配置

cd ..
.\start-knowledge-server.ps1
```

浏览器打开控制台后，右上角显示：

- **已连接**（绿点）：服务正常
- **连接失败**（红点）：请检查服务是否启动、端口是否正确

### 2.2 本地 Mock 模式

在 `.env` 中设置 `MOCK_LLM=1` 可在无 API Key 的情况下本地调试界面与流程。

## 3. 调试 · 问答

**路径**：侧栏「调试 → 问答」

### 3.1 界面说明

| 区域 | 说明 |
|------|------|
| 主区 | 候选回答列表，Markdown 渲染，含图片预览 |
| 右侧「提问」 | 问题输入、知识库、回答模型、Top K |
| 右侧「候选匹配」 | 各候选的置信度与标准问题 |
| 右侧「消耗时间 / Token」 | 单次问答的性能指标 |

### 3.2 操作步骤

1. 在右侧选择 **知识库** 与 **回答模型**
2. 设置 **Top K**（1–20，默认 5）：返回前 K 个候选
3. 输入问题，点击 **提问** 或按 **Ctrl+Enter**
4. 查看主区回答；点击候选卡片可滚动到对应回答

### 3.3 其他功能

- **清空**：清除当前问题与回答
- **随机问题**：从当前知识库已启用条目中随机抽取一条问法填入输入框

## 4. 调试 · 召回度测试

**路径**：侧栏「调试 → 召回度测试」

用于批量评测知识库召回效果：输入人工问题，运行模型匹配，人工标注是否召回正确。

### 4.1 界面说明

| 区域 | 说明 |
|------|------|
| 主区 | 气泡卡片列表，每条含问题、查看回答、是否召回 |
| 顶部统计 | 总条数、已标注数、召回率、平均耗时、平均 Token |
| 显示条数 | 10 / 20 / 50 / 不限，控制列表可视高度，滚轮浏览全部条目 |
| 右侧栏 | 知识库、Top K、回答模型；增删、运行、保存、导入、导出 |

### 4.2 操作流程

1. 选择 **知识库**（自动加载该库的召回测试数据）
2. **添加行** 或 **批量导入问题**（JSON 数组，每项含 `question` 字段）
3. 填写或编辑 **人工问题**
4. 点击 **批量运行**：
   - 有勾选 → 只运行选中且有问题文本的行
   - 无勾选 → 运行所有未标注的行（已标注「是/否」的会跳过）
5. 点击 **查看回答** 查看模型 Top-K 回答
6. 标注 **是否召回**（是 / 否 / 未标注）
7. 点击 **保存** 持久化到 `files/kb_{id}/recall_tests.json`
8. **导出 Markdown** 生成本地评测报告

### 4.3 标注说明

- 标注为 **是** 的卡片左侧显示绿色边线
- 标注为 **否** 的卡片左侧显示红色边线
- **全选** 作用于全部行，便于批量运行或删除

## 5. 管理 · 问题管理

**路径**：侧栏「管理 → 问题管理」

三栏布局：知识库列表 | 标准问题列表 | 问题编辑器

### 5.1 知识库操作

点击知识库区 **操作 ▾** 下拉：

| 操作 | 说明 |
|------|------|
| 新增知识库 | 创建新知识库 |
| 刷新列表 | 重新拉取知识库列表 |
| 重命名 | 修改显示名称 |
| 重新加载索引 | 热重载内存 FAQ 索引（修改 JSON 后若未自动刷新可用） |
| 删除知识库 | 删除整个知识库及数据（需确认） |

### 5.2 标准问题操作

点击标准问题区 **操作 ▾** 下拉：

| 操作 | 说明 |
|------|------|
| 新增问题 | 弹窗填写标准问题、变体问法、回答 Markdown |
| 批量新增 | 粘贴 JSON 数组批量导入 |
| 刷新 / 全选 / 取消全选 / 反选 | 列表勾选管理 |
| 启用选中 / 禁用选中 | 批量修改 `enabled` 字段 |
| 删除选中 | 批量删除 |

### 5.3 编辑与保存

- **表单 Tab**：编辑 ID（只读）、标准问题、变体问法、回答 Markdown（支持编辑/预览）、启用匹配
- **JSON Tab**：直接编辑单条条目 JSON
- **保存** 或 **Ctrl+S**（在管理页）保存当前条目
- 保存后系统自动 reload 知识库索引

### 5.4 批量新增 JSON 格式

```json
[
  {
    "question": "标准问题文本",
    "variants": ["变体问法1", "变体问法2"],
    "answer": "回答正文，支持 Markdown",
    "enabled": true
  }
]
```

`id` 可省略，系统自动分配 `q001` 起。

## 6. 管理 · 文件管理

**路径**：侧栏「管理 → 文件管理」

用于管理文档源文件、提取 Markdown、编辑保存。

### 6.1 界面布局

| 区域 | 说明 |
|------|------|
| 左栏 | 文件树：`sources`（PDF/MD 源）与 `modules`（提取后的 MD） |
| 中栏 | Markdown 编辑（编辑/预览 Tab）或 PDF 提示 |
| 右栏 | 上传、保存、操作菜单、提取配置、进度 |

### 6.2 上传文件

- 支持 **PDF**、**Markdown**
- 上传后保存在 `files/documents/sources/`

### 6.3 PDF 提取

1. 在文件树选择 PDF
2. 右侧配置 **页码范围**（可添加多个范围，如 1–5、56–62）
3. 点击 **开始提取**
4. 流程：Docling 逐页提取 → VLM 精修（模型见设置「文档提取模型」）
5. 完成后自动打开生成的 module Markdown

### 6.4 Markdown 源文件提取

选择 `sources` 下的 MD 文件，指定 **行范围**，同样走提取流程生成 module 文件。

### 6.5 编辑 module Markdown

1. 选择 `modules` 下的 MD 文件
2. 在中栏编辑源码或预览
3. 点击 **保存**（`PUT /markdown-files/content`）
4. 切换文件时若有未保存修改会提示确认

### 6.6 文件操作菜单

| 操作 | 说明 |
|------|------|
| 新建 MD | 在 modules 下创建新 Markdown |
| 刷新 | 重新加载文件树 |
| 重命名 | 修改文件名 |
| 删除 | 删除文件（需确认） |

## 7. 管理 · 问题生成

**路径**：侧栏「管理 → 问题生成」

从 Markdown 文档选段，自动生成 FAQ 问法并导入知识库。

### 7.1 界面布局

| 区域 | 说明 |
|------|------|
| 顶栏 | 目标知识库、新建知识库、刷新文件树 |
| 左栏 | Markdown 文件树 |
| 中左 | 行范围选择 + 已选段落列表 |
| 中右 | 带行号的 Markdown 查看器（源码/预览） |

### 7.2 操作流程

1. 选择 **导入知识库**
2. 在文件树点击 Markdown 文件
3. 设置「从 X 到 Y 行」→ 点击 **添加选择**
4. 每条选择可：
   - 手动填写标准问题与其他问法
   - 点击 **自动生成问法**（调用 FAQ 生成模型）
5. 点击 **导入到知识库** 写入 FAQ JSON（自动分配 ID，追加模式）

> 典型流程：文件管理上传 PDF → 提取 MD → 问题生成选段 → 生成问法 → 导入 → 调试问答验证

## 8. 日志

**路径**：侧栏「日志」

记录控制台各模块的操作日志，便于排查与审计。

### 8.1 功能

| 功能 | 说明 |
|------|------|
| 模块筛选 | 全部 / 调试 / 问题管理 / 文件管理 / 问题生成 / 设置 |
| 知识库筛选 | 可选特定知识库或「全部知识库」 |
| 自动刷新 | 进入日志页后每 3 秒刷新（未暂停时） |
| 暂停 / 继续 | 暂停自动刷新 |
| 清空 | 清空全部日志（需确认） |
| 刷新 | 手动拉取最近 500 条 |

日志文件：`logs/operations.jsonl`

## 9. 设置

**路径**：侧栏「设置」

### 9.1 回答模型配置

- 可添加 **多套** 完整配置（API Base URL、API Key、Model、Max Tokens、Temperature）
- 问答与召回度测试页可选择不同模型
- 至少保留一套；可设默认

### 9.2 FAQ 生成模型

- 问题生成「自动生成问法」所用 LLM 配置
- 独立于回答模型

### 9.3 文档提取模型

- PDF 逐页 Docling 提取后 VLM 精修所用 LLM 配置

### 9.4 提示词

| 类型 | 用途 |
|------|------|
| 回答模型提示词 | 问答与召回度中的语义匹配规则 |
| FAQ 生成提示词 | 由回答正文生成标准问题与变体问法 |
| 文档提取提示词 | PDF 提取时 VLM 精修 Markdown 的规则 |

各提示词区均有 **恢复默认提示词** 按钮；下方只读区域展示运行时 System Prompt 预览。

### 9.5 保存

点击右上角 **保存全部**，一次性写入所有模型与提示词配置。

## 10. 数据目录

```
knowledge_router/
  config/
    knowledge_bases.json    # 知识库注册表
    match_profiles.json       # 回答模型配置
    models.json               # FAQ / 文档提取模型
    prompts.json              # 提示词
  files/
    kb_{id}/
      questions.json          # FAQ 数据
      recall_tests.json       # 召回度测试数据
      assets/                 # 回答内图片
    documents/
      sources/                # 上传的 PDF/MD 源
      modules/                # 提取/编辑后的 MD
      assets/                 # 文档插图
  logs/
    operations.jsonl          # 操作日志
```

## 11. 推荐工作流

### 11.1 从零建库

1. **设置** → 配置回答模型、FAQ 生成模型（如需从文档建库）
2. **管理 → 问题管理** → 新增知识库 → 手动录入或批量 JSON 导入 FAQ
3. **调试 → 问答** → 验证匹配效果
4. **调试 → 召回度测试** → 批量评测召回率

### 11.2 从 PDF 文档建库

1. **设置** → 配置文档提取模型、FAQ 生成模型及对应提示词
2. **管理 → 文件管理** → 上传 PDF → 配置页码 → 开始提取
3. **管理 → 问题生成** → 选择提取后的 MD → 选行范围 → 自动生成问法 → 导入知识库
4. **调试 → 问答** → 验证
5. **调试 → 召回度测试** → 评测并导出报告

### 11.3 日常维护

- 修改 FAQ 后保存即自动 reload；若异常可用「重新加载索引」
- **日志** 页查看操作记录
- 定期备份 `config/` 与 `files/` 目录

## 13. 常见问题

**Q：提问后无回答？**  
A：检查知识库是否有启用的 FAQ 条目；查看候选匹配 Tab 是否全部为 NONE；确认回答模型 API 配置正确。

**Q：召回度测试保存后数据在哪？**  
A：`files/kb_{id}/recall_tests.json`，切换知识库会自动加载对应文件。

**Q：PDF 提取失败？**  
A：检查设置中的文档提取模型 API；查看右侧进度日志与「日志」页详细记录。

**Q：图片在回答中不显示？**  
A：确认图片已保存在 `files/kb_{id}/assets/` 或 `files/documents/assets/`，回答 Markdown 中引用路径正确。
